## Techniques

source: genesis/SKILL.md#phase-1-explode

Four EXPLODE divergence techniques. Apply at least 3 per session. Each must produce ideas distinct in angle from the others. Run until 20+ ideas are generated before any STRUCTURE step.

### 1. Absurd Amplification
**Trigger:** Idea generation stalls or all ideas cluster around the same direction; any constraint feels "obviously correct."
**Method:** Take any constraint to 10x, 100x, 1000x scale. Then take it to zero or reverse it. The 1% genius lives inside the absurd — extract it by asking "what is actually true about this absurd version that could apply at real scale?"
**What it produces:** Ideas that name implicit assumptions the original framing never questioned; ideas that reveal a different market, user, or attack surface entirely.
**STOP signal:** If the absurd version produces no insight, the constraint was not load-bearing — move to a different constraint.

---

### 2. Role Shifting
**Trigger:** Team or model converges on ONE direction without discomfort; fast agreement on a problem that warrants L3+ analysis.
**Method:** Run the problem through at least 3 roles: Child (why does it have to work that way? no assumptions), Criminal (how would someone exploit or harm this?), Competitor (where is this weakest and how would I attack it?). Each role must produce a divergent insight — not a restatement. Document the divergent insight from each role, not just the conclusion.
**What it produces:** At least ONE insight that makes the room uncomfortable. That insight typically surfaces the hidden constraint, attack vector, or defensibility gap that the shared frame made invisible.
**Key rule:** Run roles until you have at least one insight that makes the room uncomfortable. A role that produces a restatement was not genuinely adopted.

---

### 3. CROSS-Domain Stealing
**Trigger:** Idea generation is blocked past idea 10-12; all ideas reference the same domain (e.g., all software ideas).
**Method:** Name the core PATTERN of the problem (not its surface features). Find an unrelated field that solved the same pattern. Aviation, medicine, manufacturing, and urban planning each contain solutions most software problems have not borrowed. Steal the mechanism and translate it to the current domain.
**What it produces:** Ideas that no one in the domain would generate from within the domain; often reveals the most defensible architectural decisions.
**Key rule:** The stolen mechanism must be translated — not just named. "Use checklists like aviation" is not an idea. "Apply a pre-flight checklist pattern to every deployment with mandatory sign-off gates" is an idea.

---

### 4. Constraint Explosion
**Trigger:** The main constraint feels fixed and non-negotiable; ideas are all working within it.
**Method:** Take the main constraint and ask three questions: (1) What if it were 10x worse? (2) What if it were removed entirely? (3) What if it were reversed? Each question generates a distinct idea space. Solutions hide at constraint extremes because the constraint defines the boundary of the obvious solution space — going past it reaches the non-obvious.
**What it produces:** Ideas that either solve the constraint itself (removing it) or reveal that the constraint is not as fixed as assumed (reversing it).
**Key rule:** At least one idea per question. If "constraint removed" produces nothing, the constraint is not actually constraining the approach — the real constraint is elsewhere.
