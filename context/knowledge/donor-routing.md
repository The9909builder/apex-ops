# Donor routing

What failure this prevents: routing a leaf to a donor whose gate the leaf cannot satisfy,
wasting a full donor invocation.

**Donor reachability:** every donor below is symlinked into `context/donors/<name>/SKILL.md`
(relative to this skill's directory). Read the donor at route time via that path —
`context/donors/<donor>/SKILL.md` — never from a hardcoded tree and never by pasting donor
text into APEX. Verify reachability with `scripts/check-donor-sync.py` (exits 0 = all donors
resolve, gates verified). If a donor link is broken, report it in CLOSE as a skip and route
the leaf to direct execution.

Closed node-type set and their donors, with the gate that must pass BEFORE the donor fires:

| Node type | Invoke | Gate before the node passes |
|---|---|---|
| LEARN | deep-understanding (gap engine) | a specific gap named (VOCAB/MECHANISM/INTUITION/TRANSFER/RETENTION), not a topic restated |
| DECIDE contested/normative | super-reasoner (tier from that node's own risk score) | falsifiability conditions present |
| DECIDE real messy situation | realthink GROUND->CRUX->CUT | ONE leverage move, grounded |
| GENERATE | genesis explode + Goldilocks filter | >=5 ideas ranked, absurd ones included |
| RESEARCH/frontier | frontier-vision | scenario with an EDGE and a 1000x impact vector |
| BUILD | think-pipeline slots, then autovibe COMPILE | W1 step exists, buildable this week on this machine |
| SHIP | hand off to ship / land-and-deploy | routed out of scope; APEX does not ship |

Selection rules:
- A node is a LEAF when one donor chain can finish it in one pass. Non-leaf nodes decompose
  further; they are never executed.
- Each child inherits the parent System Card plus a DELTA line: what must be true for THIS
  subtree.
- Escalation: if a mid-run node shows symptoms missed at decode, stop, re-score, escalate
  inline same turn (M->D), no restart.

## Specialist donors (curated, situational)

Three additional curated donors (linked, gated, in the health baseline) route only when their
situation IS the leaf's shape:

- **sealed-substrate-architect** — BUILD leaf whose target is an existing working-but-untyped
  multi-system codebase being collapsed into one typed kernel. Gate: certified capabilities
  with ledgered actions in the rebuild plan.
- **reason** — verification leaf: run GROUND recursively over an OUTPUT, not an input. Gate:
  the answer itself passes GROUND via a named revision loop.
- **human-operating-system** — DECIDE leaf for personal life operations under uncertainty
  (boundary/stock/center/loop framing). Gate: intervention level matches the problem's level;
  observation precedes intervention.

## Catalog reach (beyond the curated table)

When no donor in the table above fits a leaf, query the generated catalog before declaring the
leaf unroutable:

```bash
python3 scripts/donor-catalog.py query --terms "<leaf terms>" --top 5
```

- `context/knowledge/donor-catalog.json` is generated by `scripts/donor-catalog.py refresh`;
  it lists every skill installed on this machine with name, description, triggers, and earned
  lane when a spec.yaml exists.
- Routing rules: a curated donor beats a catalog hit on equal fit; a catalog route marks the
  NODE line `(catalog)` and appears in CLOSE; read the cataloged SKILL.md at route time exactly
  like a curated donor (reference, never paste).
- Tie-break inside catalog hits: higher earned lane first; on equal lane, the entry with
  declared triggers beats a description-only match.
- Composition ladder: single -> pair -> chain, cap 3 donors per leaf. Pair only when the
  second donor's INPUT is the first donor's OUTPUT; chain only while every link's gate shows
  inline.
- A stale catalog routes to a skill that may no longer exist: refresh after installing or
  removing skills, and check the entry path exists before invoking.

## Outcome overrides (advisory)

Receipts and telemetry are the router's own outcome memory. Before fixing the donor order for
equal-fit candidates, consult them:

- `python3 scripts/check-receipts.py` plus `~/.kraken/outcomes/` rows show which donor actually
  passed its gate on real runs; a donor with recent passing receipts wins a tie against an
  equal-fit candidate with none.
- `python3 scripts/telemetry.py query --terms "<leaf terms>"` overrides are advisory: they may
  re-order equal-fit candidates or add a pre-route probe, never drop a leaf, and never bypass a
  gate.
- No outcome rows for a tie: the curated-beats-catalog, then higher-lane order stands. An
  override never blocks a route.
- EXPERIMENT: over the next 10 multi-candidate routings, compare receipt pass rates of
  override-picked donors against ladder-picked donors on ties; if overrides do not win ties
  better than the default ladder, this section demotes to advisory-only with no tie effect.

BUILD leaves hand off to autovibe with the CONTEXT ENVELOPE (root intent verbatim, crux,
DELTA lines, upstream artifacts, constraints); autovibe consumes it as its ANCESTRY packet
source. The envelope shape is defined in autovibe's SKILL.md `## CONTEXT PACKET` section and
both skills treat it as a binding contract.
